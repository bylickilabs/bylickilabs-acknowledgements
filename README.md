## BYLICKILABS Security Acknowledgements

> [!NOTE]
> Dieses Repository dokumentiert den **verantwortungsvollen Umgang mit gemeldeten Sicherheitsproblemen** rund um **BYLICKILABS** und **bylickilabs.de**.
>
> Im Mittelpunkt stehen **Responsible Disclosure**, **technische Verifikation**, **koordinierte Behebung** und die **öffentliche Anerkennung verantwortungsvoller Security Researcher**.

<br>

> [!IMPORTANT]
> **Ziel ist ein transparenter und nachvollziehbarer Prozess:**
>
> `REPORT` → `VERIFY` → `ASSESS` → `REMEDIATE` → `VERIFY FIX` → `ACKNOWLEDGE`
>
> Sicherheitsrelevante Hinweise werden **strukturiert gemeldet**, **technisch geprüft**, gegebenenfalls **behoben** und nach erfolgreicher Verifikation sowie Abstimmung als **Security Acknowledgement** dokumentiert.

━━━━━━━━━━━━ ◆ ━━━━━━━━━━━━

## Über dieses Repository

| Sicherheitsforschung ist ein wichtiger Bestandteil bei der kontinuierlichen Verbesserung digitaler Systeme. |
|--|

Die verantwortungsvolle Meldung von Sicherheitsproblemen trägt dazu bei, Schwachstellen frühzeitig zu erkennen, technisch zu analysieren und koordinierte Maßnahmen zur Behebung einzuleiten.

Dieses Repository dient dazu, entsprechende Beiträge strukturiert zu dokumentieren und Personen öffentlich anzuerkennen, die relevante Sicherheitsprobleme verantwortungsvoll an BYLICKILABS melden.

> [!NOTE]
> Die öffentliche BYLICKILABS Security Acknowledgement Seite mit bestätigten und freigegebenen Anerkennungen ist unter folgendem Link erreichbar:
>
> [ACKNOWLEDGEMENT](https://bylickilabs.de/security-acknowledgements.html)

<br>

> [!IMPORTANT]
> Sicherheitsrelevante Hinweise können über das dafür vorgesehene GitHub Formular eingereicht werden:
>
> [SICHERHEITSMELDUNG EINREICHEN](https://github.com/bylickilabs/bylickilabs-acknowledgements/issues/new?template=security-report.yml)

<br>

> [!WARNING]
> Enthält eine Sicherheitsmeldung vertrauliche Informationen, Zugangsdaten, personenbezogene Daten oder technische Details, deren Veröffentlichung ein zusätzliches Sicherheitsrisiko darstellen könnte, dürfen diese Informationen nicht über das öffentliche GitHub Formular eingereicht werden.
>
>
> Verwende in diesem Fall ausschließlich einen dafür vorgesehenen privaten Meldeweg. 
>
> Sensible oder vertrauliche Sicherheitsmeldungen, die nicht über das öffentliche GitHub Formular eingereicht werden sollten, bitte direkt an **[bylicki@mail.de](mailto:bylicki@mail.de)** übermitteln.

| Security Acknowledgements |

Personen können für die verantwortungsvolle Meldung sicherheitsrelevanter Erkenntnisse zu BYLICKILABS Infrastruktur, Websites, Anwendungen, Projekten oder anderen ausdrücklich einbezogenen Systemen öffentlich anerkannt werden.

```yarn 
Ein Acknowledgement kann unter anderem folgende Angaben enthalten:
```

  - Name des Security Researchers
  - Alias oder Pseudonym
  - GitHub Profil
  - Website oder berufliches Profil
  - Datum der Anerkennung
  - Allgemeine Kategorie der Schwachstelle
  - Betroffenes BYLICKILABS Projekt oder System
  - Aktueller Behebungsstatus
  - Gewünschte Form der öffentlichen Anerkennung

> [!WARNING]
> Sensible technische Informationen werden bewusst nicht veröffentlicht, wenn dadurch unnötige Sicherheitsrisiken entstehen könnten.


━━━━━━━━━━━━ ◆ ━━━━━━━━━━━━

| Geltungsbereich |
|---|

Sicherheitsmeldungen sollten sich auf öffentlich erreichbare Systeme, Websites, Anwendungen oder Projekte beziehen, die eindeutig BYLICKILABS zugeordnet werden können.

```yarn 
Nicht Bestandteil einer verantwortungsvollen Sicherheitsprüfung sind insbesondere:
```

  - Systeme oder Dienste Dritter
  - Social Engineering gegen Personen
  - Phishing oder Identitätsmissbrauch
  - Denial of Service oder vergleichbare Belastungstests
  - Destruktive Tests
  - Unautorisierte Veränderungen oder Löschungen von Daten
  - Unnötiger Zugriff auf personenbezogene oder vertrauliche Informationen
  - Weitergehende Zugriffe, sobald eine Schwachstelle bereits ausreichend nachgewiesen wurde

> [!NOTE]
> Für die Meldung einer Schwachstelle ist ausschließlich der technische Nachweis erforderlich, der notwendig ist, um das Problem nachvollziehen und verifizieren zu können.

━━━━━━━━━━━━ ◆ ━━━━━━━━━━━━

| Ablauf nach einer Sicherheitsmeldung |
|---|

```yarn
Nach Eingang einer Sicherheitsmeldung erfolgt die Bearbeitung grundsätzlich in mehreren Schritten```
```

| Schritt | Status | Beschreibung |
|:---|:---|:---|
| 01 | **REPORT** | Eingang und erste Sichtung der Meldung |
| 02 | **VERIFY** | Technische Prüfung und Reproduktion des gemeldeten Befunds |
| 03 | **ASSESS** | Bewertung von Relevanz, Auswirkung und möglichem Sicherheitsrisiko |
| 04 | **REMEDIATE** | Umsetzung geeigneter Maßnahmen zur Behebung oder Risikoreduzierung |
| 05 | **VERIFY FIX** | Überprüfung der vorgenommenen Korrektur |
| 06 | **ACKNOWLEDGE** | Optionale öffentliche Anerkennung des Security Researchers nach Abstimmung |

> [!IMPORTANT]
> Eine Aufnahme in die Security Acknowledgements erfolgt ausschließlich nach erfolgreicher technischer Verifikation und unter Berücksichtigung der vom Security Researcher gewünschten Form der öffentlichen Anerkennung.

━━━━━━━━━━━━ ◆ ━━━━━━━━━━━━

| Responsible Disclosure |
|---|

Sicherheitsrelevante Erkenntnisse sollten vor einer weitergehenden öffentlichen Veröffentlichung zunächst verantwortungsvoll an BYLICKILABS gemeldet werden.

Das hierfür bereitgestellte GitHub Formular erstellt ein öffentliches Issue. Passwörter, API Keys, Access Tokens, Private Keys, personenbezogene Daten, vertrauliche Informationen oder unnötige technische Exploit Details dürfen deshalb nicht über das öffentliche Formular übermittelt werden.

Ein Bericht sollte ausreichend technische Informationen enthalten, damit das beobachtete Verhalten nachvollzogen und soweit möglich reproduziert werden kann.

```yarn
Verantwortungsvolle Meldungen sollten:
```

  - Das identifizierte Problem eindeutig beschreiben
  - Das betroffene System oder die betroffene Komponente benennen
  - Mögliche sicherheitsrelevante Auswirkungen erläutern
  - Relevante Informationen zur Reproduktion enthalten
  - Unnötigen Zugriff auf personenbezogene oder vertrauliche Daten vermeiden
  - Destruktive Tests vermeiden
  - Beeinträchtigungen produktiver Systeme vermeiden
  - Ausreichend Zeit für technische Analyse und Behebung ermöglichen

> [!CAUTION]
> Eine weitergehende öffentliche Offenlegung technischer Details sollte erst nach angemessener Koordination sowie nach Prüfung und gegebenenfalls Behebung des gemeldeten Problems erfolgen.

━━━━━━━━━━━━ ◆ ━━━━━━━━━━━━

| Anerkennung |
|---|

```yarn
Eine öffentliche Anerkennung dient der Würdigung verantwortungsvoller und konstruktiver Sicherheitsforschung.
```

> Eine Anerkennung kann erfolgen, wenn:
  - Ein gemeldetes Problem technisch nachvollzogen oder bestätigt werden kann
  - Die Meldung ein relevantes BYLICKILABS System oder Projekt betrifft
  - Grundsätze verantwortungsvoller Offenlegung eingehalten wurden
  - Durch die Untersuchung keine vorsätzlichen Schäden oder unnötigen Beeinträchtigungen verursacht wurden
  - Keine vertraulichen oder sensiblen Informationen unangemessen veröffentlicht wurden
  - Eine öffentliche Anerkennung für die gemeldete Erkenntnis angemessen ist

> [!NOTE]
> Security Researcher können auf Wunsch unter ihrem echten Namen, einem Alias oder Pseudonym genannt und mit einem freigegebenen öffentlichen Profil verlinkt werden.
>
> Eine anonyme Anerkennung ist ebenfalls möglich.

━━━━━━━━━━━━ ◆ ━━━━━━━━━━━━

| Grundsätze der Sicherheitsforschung |
|---|

```yarn
BYLICKILABS unterstützt Sicherheitsforschung auf Grundlage von:
```

  - Technischem Verständnis
  - Responsible Disclosure
  - Reproduzierbarer Analyse
  - Respekt vor Privatsphäre
  - Schutz sensibler Informationen
  - Koordinierter Behebung
  - Transparenter Kommunikation
  - Ethischer Sicherheitsforschung

> [!TIP]
> Sicherheitsforschung sollte dazu beitragen, Systeme zu verbessern, ohne unnötige Risiken für Nutzer, Infrastruktur oder Dritte zu verursachen.
